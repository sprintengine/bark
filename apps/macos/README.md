# Fairspoken for macOS (native)

Two native apps for macOS 26 on Apple Silicon, built from one XcodeGen project and a set of shared
Swift packages:

| App | Bundle id (Release / Debug) | What it is |
|---|---|---|
| **Fairspoken** (`Fairspoken.app`, scheme `Fairspoken`) | `ie.fairspoken.mac` / `.dev` | Menu-bar dictation: speech recognition on the Apple Neural Engine (Parakeet through FluidAudio, Whisper through WhisperKit; Core ML), a dashboard with a frosted sidebar and solid content (Home, Models, Post-training, Settings), a setup guide, a floating recording pill, and optional transcription on your own host |
| **Fairspoken Server** (`Fairspoken Server.app`, scheme `FairspokenServer`) | `ie.fairspoken.server` / `.dev` | A transcription server for a practice or a team: the host protocol of `src-tauri/src/host/PROTOCOL.md` on Parakeet and the Neural Engine, with a live view of who is dictating, models, configuration and the address clients need |

Fairspoken (Mac), the Windows and Linux desktop app and the web dashboard all talk to Fairspoken
Server exactly as they talk to the Rust `transcription-host`. The architecture follows
`swift-macos-app_plan.md` at the repo root.

## Build, test, run, install

```sh
cd apps/macos
brew install xcodegen                 # once
scripts/setup-signing.sh              # once per machine: a stable signing identity (see below)
scripts/build.sh                      # Debug, both apps → build/Build/Products/Debug/{Fairspoken,Fairspoken Server}.app
scripts/build.sh release              # Release, both apps
scripts/build.sh --app server         # one app: client | server | all
scripts/test.sh                       # unit tests: FairspokenCore (197), FairspokenHost (78), FairspokenUpdates (19), FairspokenSpeech (11)
scripts/install.sh                    # Release Fairspoken → ~/Applications, then launches it
scripts/install.sh --app server       # the same for Fairspoken Server (--app all for both)
scripts/release.sh                    # Developer ID + notarized → build/release/Fairspoken-<version>-macos-arm64.{zip,dmg}
scripts/release.sh --app server       # → build/release/Fairspoken-Server-<version>-macos-arm64.{zip,dmg}
scripts/screenshots.sh                # docs/screenshots/ (client) and docs/screenshots/server-app/ (server), not committed
open "build/Build/Products/Debug/Fairspoken Server.app"
```

`scripts/build.sh [release] [--app …] [SETTING=value ...]` passes extra build settings to xcodebuild
(`scripts/build.sh MV_SIGN_IDENTITY=-` builds ad-hoc, as CI does). `scripts/release.sh` is what the
release workflow runs, once per app; before its first local run, store the notarization credentials
with `xcrun notarytool store-credentials fairspoken-notary --apple-id <apple id> --team-id <TEAM_ID>`
(`--no-notarize` and `--unsigned` skip that). See `docs/releasing.md` at the repo root.

The `.xcodeproj` is generated by XcodeGen and git-ignored. Run `xcodegen generate` and open
`Fairspoken.xcodeproj` to work in Xcode (schemes `Fairspoken` and `FairspokenServer`).

## Fairspoken Server

### What it serves

- Every route of `PROTOCOL.md`: `GET /` (the web dashboard, `src-tauri/src/host/dashboard.html`
  bundled at build time, never copied), `/favicon.ico`, `/v1/health`, `/v1/stats`, `/v1/events`
  (SSE: snapshot first, `: ping` every 15 s, 16 subscribers, slow ones dropped at 256 frames),
  `POST /v1/config`, `/v1/models/download`, `/v1/transcriptions` (WAV) and
  `/v1/transcriptions/stream` (framed PCM16 over a chunked body).
- Bearer token on every route except `/` and `/favicon.ico`, `?token=` on GET only, compared in
  constant time. The `x-fairspoken-*` headers, ids, event types, ordering rules, status codes and
  error strings are the Rust host's; `shared/host-conformance/` checks both hosts with the same suite.
- Behind `tailscale serve` (loopback), the client is the first `X-Forwarded-For` /
  `Tailscale-User-Login` value; those headers are trusted from loopback only.
- Discovery and pairing: `GET /v1/hello` and `POST /v1/pair` need no token. With a pairing password
  set, a client that scans the tailnet trades it for the token (5 wrong tries per address, 20 in all,
  per 10 minutes, then `429`). Scans probe `https://<name>.ts.net` (`tailscale serve`) and the
  Tailscale IP on port 48173, so at 127.0.0.1 the server is found only through `tailscale serve`.
- Models: **Parakeet TDT 0.6B v3** and **Parakeet Ultra**, on the Neural Engine. Each worker owns a
  decoder; workers on the same model share one copy of its weights (the FluidAudio spike measured 8
  concurrent decoders as correct, at ~2.1× the throughput of one). Parakeet Redux is not offered
  (its encoder runs mostly on the CPU on M4 + macOS 26). Models live in FluidAudio's shared cache,
  `~/Library/Application Support/FluidAudio/Models/`, which Fairspoken on the same Mac also uses.
- Streams are decoded while the client speaks: once 12 s are buffered, the audio is cut at the
  quietest 20 ms between 7 and 12 s and that segment decoded at once, so at release only the tail
  (≤ 12 s, 40–80 ms on the Neural Engine) is left. A streamed job's `processingMs` runs from the end
  of its upload, so it is the server's release-to-text, including any wait for a free worker.
- Vocabulary hints are accepted and not applied (the client restores its own casing); the
  `x-fairspoken-language` header is accepted and ignored, as Parakeet detects the language.

Measured on the M4 (Release build, 100 ms frames sent in real time, 2 workers):

| | Fairspoken Server | Rust host (ONNX) |
|---|---|---|
| 4 s dictation, release → text | 72–91 ms | 133–136 ms on a quiet machine (820–1130 ms under load in one run) |
| 60 s dictation, release → text | 135–156 ms | 161–199 ms |
| 8 people releasing within 0.3 s, 4 s each | 111–151 ms each | not measured |
| Fairspoken (Mac) → server, `--selftest` | 114 ms (4× real-time upload) | |

The first launch of a new build compiles the encoder for the Neural Engine (13–25 s, once per model
path and macOS build); later launches load in under a second.

### Run modes

1. **App** (default): a menu-bar item (status, server address, copy token, start/stop, start at
   login) and a window: Activity (counters and the live constellation of clients → queue → workers →
   models), Clients, Models (download, delete, per-worker model), Connect (address, token, QR code)
   and Configuration. The toolbar's Live/Demo switch shows a simulated practice server instead of
   this one (the real server keeps serving). The window reads the host in-process: the same snapshot
   and event frames as `/v1/events`, decoded by the `HostEvent`/`HostLiveState` code in FairspokenCore.
2. **Start at login**: Configuration › This Mac › Start at login (`SMAppService.mainApp`). The app
   opens in the menu bar when you log in; System Settings › General › Login Items lists it.
3. **Headless**: `Fairspoken Server.app/Contents/MacOS/Fairspoken Server --headless` serves with no UI
   and logs one line per job (never transcript text) to standard output; SIGTERM / SIGINT stop it
   cleanly. As a per-user LaunchAgent (starts at login, restarted by launchd if it exits abnormally):

   ```sh
   scripts/server-agent.sh install [--app "/Applications/Fairspoken Server.app"] [--env KEY=VALUE ...]
   scripts/server-agent.sh status
   scripts/server-agent.sh uninstall
   ```

   Tested on this Mac: the agent served Neural Engine transcription (79 ms release → text) and launchd
   restarted it 1 s after a `kill -9`. Don't run the app at the same time (same port).

   **LaunchDaemon (no user logged in): not tested.** It should work with the same `--headless`
   command in `/Library/LaunchDaemons/` with a `UserName` key set to a normal account, so the server
   reads that account's FluidAudio model cache and config. Run as root it would look in
   `/var/root/Library/…` instead. Whether the Neural Engine is available before any login was not
   verified. Two caveats from the spike: keep `StandardOutPath` off external volumes (launchd exits
   78 when it can't open the log there), and expect the encoder compile on the first run per account.
4. **Keep awake**: while serving, the app and headless mode hold a `PreventUserIdleSystemSleep` power
   assertion (`pmset -g assertions` shows it), so the Mac doesn't idle-sleep; the display can still
   sleep. Configuration › This Mac › "Keep this Mac awake while serving" (`preventSleep`) turns it off.

### Configuration

`~/Library/Application Support/<bundle id>/host-config.json` (mode 0600; it holds the token). The
first four fields are the Rust host's file (`PersistedHostConfig`), so either host reads the other's:

```json
{
  "maxActiveStreams": 4, "maxRecordingSeconds": 600, "useGpu": true,
  "workerModels": ["parakeet-tdt-0.6b-v3", "parakeet-tdt-0.6b-v3", "parakeet-tdt-0.6b-v3", "parakeet-tdt-0.6b-v3"],
  "workerCount": 4, "queueCapacity": 8, "bindAddress": "127.0.0.1", "port": 48173,
  "token": "…", "pairingPassword": "…", "name": "Studio Mac", "preventSleep": true
}
```

- First launch writes defaults with a random token (32 random bytes, base64url). `pairingPassword`
  (6–128 characters, left out when off) and `name` (what a scan shows; this Mac's name when unset)
  apply at once, from the window or `POST /v1/config` (which takes `pairingPassword` but never shows
  it). A pairing password on a host without a token generates and saves one. An unreadable file stops the
  server (the window offers to reset it) rather than serving a configuration nobody chose.
- `maxActiveStreams`, `maxRecordingSeconds`, `useGpu` (here: Neural Engine on, CPU off) and
  `workerModels` change live, from the window or `POST /v1/config`, and are saved. Worker count,
  queue capacity, address, port and token restart the server when saved in the window.
- `bindAddress`: `127.0.0.1` (default, this Mac only; pair with `tailscale serve --bg 48173` to reach
  it on your tailnet over HTTPS), `0.0.0.0` (every network), or one address (e.g. the Tailscale IP).
- `modelLinks` (left out when empty): a download link per model id; see *Model download links* below.
  `FAIRSPOKEN_MODEL_LINKS` (whitespace-separated `id=link` pairs) sets links for a run over the file's;
  an unknown id, a pair that isn't `id=link` or an invalid link (in either) stops the server with the reason.
- Environment variables (headless and testing; the same names as the Rust host):
  `FAIRSPOKEN_HOST_CONFIG_PATH`, and for this run `FAIRSPOKEN_HOST_ADDR`, `FAIRSPOKEN_HOST_TOKEN`,
  `FAIRSPOKEN_HOST_PAIRING_PASSWORD`, `FAIRSPOKEN_HOST_NAME`, `FAIRSPOKEN_HOST_WORKERS`, `FAIRSPOKEN_HOST_QUEUE_CAPACITY`; `FAIRSPOKEN_HOST_MODEL`,
  `FAIRSPOKEN_HOST_MAX_ACTIVE_STREAMS`, `FAIRSPOKEN_HOST_MAX_RECORDING_SECONDS` and
  `FAIRSPOKEN_HOST_USE_GPU` only seed a first boot (the saved file wins afterwards, as in the Rust host).
  The older `MULTIVOICE_HOST_*` names are still read when the new one is unset.
  `--config <file>` points the app at another config file.

### Checking a host

```sh
# The Swift server headless on a test port, then the language-neutral suite (Node 22, no deps):
FAIRSPOKEN_HOST_ADDR=127.0.0.1:48981 FAIRSPOKEN_HOST_TOKEN=secret FAIRSPOKEN_HOST_WORKERS=1 \
FAIRSPOKEN_HOST_QUEUE_CAPACITY=2 FAIRSPOKEN_HOST_CONFIG_PATH=$(mktemp -d)/host-config.json \
  "build/Build/Products/Debug/Fairspoken Server.app/Contents/MacOS/Fairspoken Server" --headless &
node ../../shared/host-conformance/run.mjs --url http://127.0.0.1:48981 --token secret --slow
```

`Packages/FairspokenHost` also builds `fairspoken-host-dev` (`swift run fairspoken-host-dev`): the
real HTTP server, queue and workers over a stub engine, for protocol work without models.

## Fairspoken (dictation client)

Settings › Transcription › **Network device** holds the host URL, token (Keychain) and timeout, a Test
connection button and a status line such as "Using host: practice-mini.local:48173 · connected"
(one `GET /v1/health` when Settings or Home opens, or on Test; no background polling). Monitoring a
host is Fairspoken Server's job (or the web dashboard at the host's `/`); the client has no Server view.

### Text while speaking

Settings › General › **Show text while speaking** (`showTextWhileSpeaking`, on by default, a Mac-only
key) grows the recording pill to show the newest line or two of what you have said, under the level
bars; with Reduce Motion it changes without animating. It works with on-device transcription
(`LiveTranscriptionSession` in FairspokenCore): about every 0.45 s the audio not yet in a finished
segment is decoded again by the loaded Parakeet model, and once that reaches 12 s it is cut at the
quietest 20 ms between 7 and 12 s and decoded once, so no decode exceeds the model's 15 s window.
Silence after a decode is skipped, and the interval stretches so the Neural Engine is never busy more
than a fifth of the time. The text inserted still comes from one pass over the whole recording, exactly
as with the setting off, so accuracy is unchanged. With a remote host the pill shows no text (the host
protocol has no partial results).

Decoding a growing tail was chosen over FluidAudio's streaming managers: its sliding-window manager
emits text only once per window (the first words after 3–5 s, then every 4–11 s) and duplicates or
splits words where windows meet, and its true streaming models are separate downloads.

Measured on the M4 with Parakeet TDT v3 (recordings played in real time in 100 ms frames;
`FAIRSPOKEN_LIVE_TEXT_CLIPS=a.wav,b.wav swift test --filter LiveText` in `Packages/FairspokenSpeech`):

| Recording | First words | Updates | Decode, mean (longest) | Neural Engine busy | Extra CPU | Release → text, live vs off |
|---|---|---|---|---|---|---|
| 3 s | 0.52 s | every ~0.5 s | 49–56 ms (70 ms) | 9–11% | 7–8% of one core | 52–56 ms vs 50–53 ms |
| 11 s | 0.53–0.55 s | every ~0.55 s | 71–79 ms (122 ms) | 13–14% | 12–15% of one core | 106–116 ms vs 98–154 ms |
| 86 s | 0.52–0.53 s | every ~0.6 s | 92–120 ms (402 ms) | 17–20% | 17–19% of one core | 493–613 ms vs 375–503 ms |

In a third run on a busy machine (other builds running; setting-off release → text 154–923 ms) decodes
took 144–292 ms on average, so the interval stretched to 0.65–1.7 s between updates, holding the Neural
Engine at 19–20% and the extra CPU at 8–10% of one core. The inserted text matched the setting-off
transcript word for word on every recording in every run.

## Where the text goes

With **Paste into the current app** on, a dictation is put on the clipboard and pasted with ⌘V; with **Restore
clipboard afterwards** on, the previous clipboard comes back shortly after. Before pasting, the app asks
Accessibility what has focus in the frontmost app (`PasteTarget` in FairspokenCore). When there is
clearly no text field (a button, a list, an image, the Finder desktop, an app with no window), it
does not paste or restore: the dictation stays on the clipboard and the pill says "Copied — no text
field. Press ⌘V to paste." for about 4 s. Anything unclear (apps that report little to
Accessibility, such as terminals and web-view apps) is pasted as before. If a different app is in
front than when recording started, the text is pasted but the old clipboard is not restored, so the
dictation can still be pasted again.

## Learning from your corrections

**Settings › Vocabulary › Learn from your corrections** (`learnFromEdits`, on by default) is the
Tauri app's edit watcher, ported. As a recording ends, while it is transcribed, the app reads the
focused field it will paste into (its text and selection, for the text either side of the
dictation). It reads that field again when the next dictation starts, when another app or field
takes focus, or after 60 s, finds the dictation by its surrounding text and diffs it word by word
(`EditDiff` in FairspokenCore). A 1–3-word replacement that sounds like what was written ("cloud
code" → "Claude Code") is a fix; rewrites, insertions and unrelated replacements are ignored.

Fixes go to `learned.json` (the Tauri app's format: word pairs, sighting counts and the speech models
that misheard them, never the sentence) and are promoted by `LearnedStore`'s rules: an uncommon
capitalised name or term joins Your terms on the first fix; a mapping becomes a correction, scoped to
those speech models, after two; a mapping between two medicine-like words (the suffix rules, a
look-alike/sound-alike list and every medicine in the bundled Irish general practice pack) or a
single short word waits under Suggestions for Accept or Dismiss. Learned entries carry a Learned
marker; once applied, accepted or dismissed a pair is never promoted again, so a deleted one stays
deleted. Corrections, manual and learned, are applied to every dictation after casing (not with `postProcess`
off, as in the Tauri app). Until this app has its own `learned.json`, it reads the Tauri app's, so
what was dismissed or deleted there stays that way.

Never read: password managers, terminals, secure fields, fields without a plain-text value and
values over 100,000 characters. Every read is time-limited (250 ms before insertion, 500 ms after) and off the main thread, a read
still running when the paste starts is not used, and insertion never waits for it. When the dictation
was kept for post-training, the edited text is attached to it as `editedText`.

Electron apps and Chromium browsers only expose their text fields to Accessibility clients they know
about. When a recording starts in one (Electron is found by its `Electron Framework.framework`), the
app sets `AXManualAccessibility` on it, the attribute Electron and Chromium provide for this, so
the field can be read by the time the dictation is pasted. `AXEnhancedUserInterface`, which changes
how some apps animate and place their windows, is never set. `--ax-probe` (Developer switches)
reports whether the field in front can be read.

## Post-training recordings

**Post-training › Save recordings for post-training** (`trainingCapture`, off by default) keeps each
dictation's audio (16 kHz mono 16-bit WAV) and text, in the Tauri app's layout and format
(`docs/training-data.md` at the repo root), so `training/` tools read either. They go to
`~/Library/Application Support/<bundle id>/training-data/` unless you choose a folder
(`trainingDataFolder`; the app makes `Fairspoken Training Data` inside the one you pick). A chosen folder
is never created at save time: when its drive isn't connected, dictation carries on and nothing is
kept. Recordings stay until deleted on that screen; deleting asks first and moves them to the
Trash (permanent deletion only after a second confirmation, on a drive without a Trash). Only the
folders `index.jsonl` names are ever touched. The Post-train button stays disabled until the
training step ships.

## Speech models and engines

The client runs two model families on the Neural Engine, one model loaded at a time
(`LocalSpeechRouter` in `FairspokenWhisper`):

| Engine | Models | Where the files live |
|---|---|---|
| FluidAudio 0.17.5 | Parakeet TDT 0.6B v3 (default), Parakeet Ultra, Parakeet TDT 0.6B v2 | FluidAudio's shared cache, `~/Library/Application Support/FluidAudio/Models/` |
| WhisperKit 1.1.1 | Whisper tiny, base, small, medium (each also `.en`), large-v2, large-v3, large-v3-turbo; Distil-Whisper large-v3 | `~/Library/Application Support/Fairspoken/Models/WhisperKit/`, in the Hugging Face layout (`models/argmaxinc/whisperkit-coreml/<variant>/`, tokenizers in `models/openai/whisper-<size>/`) |

- **Catalogue** (`SpeechModelCatalog` in `FairspokenCore`): id, name, family, vendor, engine, kind
  (speech; cleanup models and remote endpoints will be rows of the same table), languages and an
  English-only flag, download size, memory, local or remote, licence, source, and the measured
  word error rate and speed behind the 1–5 bars (`ScoreScale`). Whisper ids are the Tauri app's
  (`tiny`, `base`, `small`, `medium`, `large-v2`, `large-v3`, `large-v3-turbo`), so one settings.json
  means one model in both apps; `.en` and `distil-large-v3` are Mac-only, and the Tauri app falls
  back to its default for them. An id neither app knows falls back to Parakeet v3.
- **Variants** are the repository's folder names; the compressed ones are used where offered
  (`openai_whisper-small_216MB`, `openai_whisper-large-v3_947MB`,
  `openai_whisper-large-v3-v20240930_626MB` for large-v3-turbo, …).
- **Whisper downloads** fetch the Core ML bundles and the tokenizer, then compile once for the
  Neural Engine ("Optimising for this device…"); a marker file says the download finished, so an
  interrupted one is never taken for installed and resumes on the next try. Cancelling stops the
  transfer. Deleting removes that model's folder, only ever inside the models folder after
  resolving `..` and symbolic links (`ModelStorage`).
- **Decoding:** greedy, without timestamps, in the dictation language (`language`; `auto` detects
  it; `.en` models always English), with Whisper's usual temperature retries when the text looks
  like a loop; recordings over 30 s are cut at pauses. Vocabulary is passed as Whisper's prompt
  (at most 100 tokens). Download links (below) are Parakeet-only for now.
- **Figures:** see `docs/model-benchmarks.md` for how speed and accuracy were measured.
- The server (Fairspoken Server) still serves Parakeet only and doesn't link WhisperKit.

**Models library** (Fairspoken › Models): one table of every model, built from reusable solid
content components in `FairspokenUI` (`ContentCard`, `Hairline`, `ScoreBar`, `Badge`,
`SortHeader`, `ContentSearchField`, `ProgressStopButton`; metrics in `ContentMetrics`). Each row has
a star (favourites list first; `favoriteModels`), the name with EN / NEW / Recommended / In use
badges, the engine, speed and accuracy bars, size, and Download, a progress ring that stops the
download, Use (… › Delete…, with confirmation) or In use. Search, engine, language, Downloaded and
On this Mac filters, and sorting by name, speed, accuracy or size, are `ModelCatalogueQuery`.
Clicking a row opens a detail sheet: description, figures and where they come from, languages,
download, memory, licence, source repository, Download from Link… (Parakeet) and **Use this model**.
Every way of choosing a model (the library, the sheet, Settings, onboarding, launch) goes through
`ModelLibrary.use` (`ModelActivation`): a model that isn't downloaded is downloaded on its row first
(cancellable) and then used, and a choice made while a dictation is recording or transcribing is
loaded once it ends.

`--selftest <wav> --model large-v3-turbo` runs any catalogue model through the same engine as
dictation (downloading it first if needed).

## Model download links

For networks that can't reach the standard model download: a Parakeet model's detail sheet on
Fairspoken › **Models** and its card on Fairspoken Server › **Models** have **Download from Link…**
while the model isn't downloaded. Give it a link to an archive of the model (or Choose File… on this
Mac or a mounted share); it is saved for that model and the download starts, with progress on the
row and any error in the sheet. A model with a saved link shows
"Downloads from host/path" and **Use Standard Download**, which removes it. Every download of that
model (Models, first-run loading, the server's Download and `POST /v1/models/download`) uses the link.

- Saved as `modelLinks` (`{"parakeet-tdt-0.6b-v3": "https://…"}`) in the client's settings.json and the
  server's host-config.json. The Tauri app's `modelLinks` (ONNX models) is never imported.
- A link is `http://` or `https://` (query strings kept, `#fragment` dropped, `user:password@` refused;
  plain `http://` only on the local network, App Transport Security), or an absolute path, `~/…` or
  `file://` URL of an archive file; at most 2048 characters. Messages and logs show `scheme://host/path`,
  never the query string.
- The archive: zip, tar or tar.gz, told apart by content, not name. It is unpacked with `/usr/bin/ditto`
  or `/usr/bin/tar` in a temporary folder; entries outside it (absolute, `..`, links pointing out),
  more than 8 GiB or more than 10,000 entries are refused. The model's folder is the shallowest one
  (the archive's root included) holding its Core ML bundles and `parakeet_vocab.json`
  (`Preprocessor.mlmodelc`, `Encoder.mlmodelc`, `Decoder.mlmodelc`, `JointDecision.mlmodelc` or
  `JointDecisionv3.mlmodelc`), so `scripts/models/make-model-bundle.sh <id> mac <out.zip>`'s layout
  (files at the root) and one nested a folder or more down both work. Those bundles and the other
  top-level files are copied into FluidAudio's cache through a staging folder and checked with
  `AsrModels.modelsExist`; the temporary files are removed either way.
- Parsing, format detection, unpacking and the install live in `FairspokenCore` (`ModelLink.swift`,
  `ModelArchive.swift`, `ModelLinkInstaller.swift`); `ParakeetModels` in `FairspokenSpeech` supplies
  the file list, destination and check. An opt-in test installs a real archive into a temporary folder
  and loads it: `FAIRSPOKEN_REAL_MODEL_LINK=<link or path> FAIRSPOKEN_REAL_MODEL_LOAD=1 swift test` in
  `Packages/FairspokenSpeech`.

## Updates

Both apps update themselves with [Sparkle 2](https://sparkle-project.org) (2.10.0, SPM), behind
`Packages/FairspokenUpdates`: an `UpdateController` with a custom Sparkle user driver, so updates show
in the app's own UI rather than Sparkle's windows.

- **Where:** the update button at the foot of the sidebar (sync → spinning while checking → download
  with a `1` badge → progress ring → restart with a dot; a warning dot after an error), a toast once
  per version ("Fairspoken 0.3.0 is available" · Later · Update), app menu › Check for Updates…, the
  menu bar item, and Settings › Updates (Fairspoken) / Configuration › Updates (Fairspoken Server),
  whose sidebar item carries a badge while an update waits. Nothing downloads until you click Update;
  a restart installs it.
- **When:** about 30 s after launch, then every 6 hours (`SUScheduledCheckInterval` 21600), and on
  demand. Headless Fairspoken Server (`--headless`) never checks: update the app it runs from.
- **Channels:** `stable` and `nightly`, saved as `updateChannel` in the app's defaults. With none
  saved, a build resolves it from its own version (`-nightly.` in `CFBundleShortVersionString` →
  nightly) and saves that on first launch, so a nightly install stays on nightly after it installs a
  promoted stable build. Changing it checks at once. Nightly allows the appcast's `<sparkle:channel>nightly</sparkle:channel>`
  items; stable only the default channel. Sparkle never downgrades, so a nightly switched to Stable
  stays put until the next stable release (Settings says so).
- **Feeds** (one appcast per app, both channels in it, on the rolling `update-feeds` release):
  - Fairspoken: `https://github.com/sprintengine/speakeasy/releases/download/update-feeds/appcast-fairspoken.xml`
  - Fairspoken Server: `https://github.com/sprintengine/speakeasy/releases/download/update-feeds/appcast-fairspoken-server.xml`
- **Versions:** Sparkle compares `CFBundleVersion` = `CURRENT_PROJECT_VERSION`, which releases set to the
  UTC build timestamp `YYYYMMDDHHMM` (`xcodebuild … CURRENT_PROJECT_VERSION=202610051200`). Local builds
  keep `1`. Updates must be EdDSA-signed with the key whose public half is `SUPublicEDKey` in both
  Info.plists.
- **Signing:** neither app is sandboxed, so Sparkle's XPC services aren't needed. The *Sign Sparkle
  helpers* build phase (`scripts/sign-sparkle.sh`) removes them and signs Sparkle's `Autoupdate` and
  `Updater.app` with the build's identity, the hardened runtime and `OTHER_CODE_SIGN_FLAGS`, which
  notarization needs (Sparkle ships them ad-hoc signed).

**Testing against a local appcast (Debug builds only).** Release builds always use `SUFeedURL`.

```sh
# An appcast with sparkle:version above 1, served from this Mac (ATS allows plain HTTP to localhost):
python3 -m http.server 18765 --bind 127.0.0.1 --directory /path/to/appcast-dir &
"build/Build/Products/Debug/Fairspoken.app/Contents/MacOS/Fairspoken" \
```

The launch check runs after ~30 s; `log stream --info --predicate 'category == "updates"'` shows what
was found. To look at the UI without a feed, `-FAIRSPOKEN_UPDATE_STATE idle|checking|available|downloading|ready|error`
(plus `-FAIRSPOKEN_UPDATE_TOAST YES`) shows that state and never starts Sparkle (Debug builds), and
`--screenshots <dir> --updates` captures every state in light and dark.

## Permissions you grant (once per signing identity + bundle id)

Fairspoken:

| Permission | Why | Where |
|---|---|---|
| Microphone | To record while the shortcut is active | System prompt (onboarding "Allow…") |
| Accessibility | To send ⌘V into the frontmost app and to detect secure/password fields. Without it, text is copied only | System Settings › Privacy & Security › Accessibility: switch on **Fairspoken** |
| Input Monitoring | Only for "hold fn to dictate" (a listen-only event tap) | System Settings › Privacy & Security › Input Monitoring |

The setup guide (shown at first launch, whenever the microphone isn't allowed, and from Settings ›
General › Setup guide or the menu bar) walks through: permissions with live status, a microphone test,
choosing a model from the catalogue (it downloads in the background), the shortcut, a place to try it,
and a live checklist of what is set up, with a fix for anything that isn't. It always reopens at its
first step, and closing or hiding it stops its microphone test. For hold-fn, also set
System Settings › Keyboard › "Press 🌐 key to" › **Do Nothing**. If the Tauri app is running, quit it or
change one app's shortcut, because both default to ⌘⇧1.

Fairspoken Server needs no privacy permission to serve loopback. Listening on `0.0.0.0` or a LAN
address may bring up macOS's Local Network prompt the first time another device connects; allow it.

**Signing and TCC:**
- macOS keys these grants on the bundle id *and* the code signature's designated requirement.
- Ad-hoc builds change signature on every build, which silently revokes Accessibility.
- `scripts/setup-signing.sh` writes `Config/Local.xcconfig` (git-ignored). It uses an Apple Development or
  Developer ID identity if one is installed, and otherwise creates a self-signed "Fairspoken Local Signing"
  certificate that you trust once in Keychain Access.
- Debug and Release use different bundle ids, so each needs its own grants and they never clobber each other.
- **Changing the bundle id or signing identity later resets every user's grants.**

## Naming and identifiers

- **Display names:** `MV_DISPLAY_NAME` in `Config/Base.xcconfig` (Fairspoken) and `Config/Server.xcconfig`
  (Fairspoken Server). They flow into `CFBundleDisplayName` and the .app names; Swift reads them back
  (`AppInfo.displayName`, `ServerInfo.displayName`). Release files are `<client name>-…` and
  `<client name>-Server-…`.
- **Bundle ids:** `MV_BUNDLE_ID_BASE` in the same files; Debug appends `.dev` (`Config/Debug.xcconfig`).
  `Config/Server-{Debug,Release}.xcconfig` include the client's and then `Server.xcconfig`, so version,
  signing and Swift settings are shared.
- **Brand:** `FairspokenUI` holds the palette (`Color.fs*` from `design/brand/README.md`: Copybook Blue,
  Margin Red for the signal only, Limestone/Night, status colours) and the mark (`FairspokenMark`, the
  logo's own paths). The server follows the brand's Liquid Glass rules: glass only on the control layer
  (sidebar, toolbar, constellation nodes); cards, tables and charts are opaque. The client puts its
  sidebar on the window's frost and its content on solid cards (`design/crystal/README.md` › Fairspoken
  for Mac). The server icon is the brand's dark icon
  composite (`scripts/make-server-icon.sh`); no taglines anywhere.
- **Wire identifiers** (per `PROTOCOL.md`): the `x-fairspoken-*` headers, the
  `application/vnd.fairspoken.pcm-stream` content type, `FAIRSPOKEN_HOST_*` and the client id `fairspoken-macos`.

**Why Network.framework rather than Hummingbird / SwiftNIO:** the host needs exact control of the wire
(SSE flushed per frame as one chunk, close-delimited bodies for HTTP/1.0, the response to an early 4xx
while a stream is still uploading, `Expect: 100-continue`), a streaming request-body reader for the frame
protocol, and binding to one interface address. Network.framework does all of that with no dependency
tree (SwiftNIO, swift-log, swift-metrics, swift-collections…); the HTTP/1.1 codec is ~400 lines, pure,
and unit-tested on its own, and the server is tested end to end over in-memory pipes and real sockets.

Client data lives in `~/Library/Application Support/<bundle id>/`. On first launch the client imports
`~/.config/fairspoken/{settings,transcript-history,usage-stats}.json` once. Secrets move to the
Keychain, and the JSON keeps empty strings. Keys the app doesn't model are preserved on save.
